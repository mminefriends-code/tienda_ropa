DISCREPANCIAS CON EL CASO DE USO (documentadas en notas)
================================================================
1. El caso describe Angular (LoginComponent, AuthService, AuthGuard) y FastAPI.
   La implementación real es React/Vite (Login.tsx, AuthContext.tsx, api.ts)
   con NestJS (CTR_Auth.ts, SRV_AuthService.ts).

2. El cuerpo real es { credencial, password } y no { email, password }.
   AuthService.buscarPorCredencial() acepta LOWER(email) o ci.

3. No existe AuthGuard. El campo del formulario se rotula
   "Correo electrónico o usuario" y el botón es "Ingresar".

4. No existen las rutas /inicio, /sucursal ni /caja. Login.tsx navega a
   destino, o a /admin para Administrador, Encargado de Sucursal y Cajero,
   y a / para clientes.

5. access_token dura 15 minutos (JWT_ACCESS_TOKEN_MINUTES, por defecto 15),
   no 8 horas. refresh_token dura 7 días (JWT_REFRESH_TOKEN_DAYS).
   El payload es { sub, rol, permisos, type, jti, iat, exp } y no incluye email.

6. Almacenamiento: AuthProvider escribe access_token y usuario en localStorage,
   y AuthController fija además cookies httpOnly access_token y refresh_token
   con sameSite lax y path /. No existe la cookie session_tt ni sessionStorage.
   No hay cliente Flutter.

7. La respuesta usa la clave "usuario" con { id, nombre, email, rol, permisos }
   y no incluye avatar. No existe columna usuarios.rol: el rol se obtiene
   por usuarios_roles.

8. Excepciones: usuario inexistente, estado distinto de 'activo' o contraseña
   incorrecta devuelven 401 "Credenciales inválidas.". No hay 403 de cuenta
   deshabilitada ni 429 con minutos restantes. Una cuenta bloqueada devuelve
   423 Locked y no hay countdown.

9. Bloqueo: al quinto fallo se guarda bloqueado_hasta = NOW() + 15 minutos y
   se reinicia intentos_fallidos a 0. El trigger fn_incrementar_intentos de
   schema.sql además pone estado = 'Bloqueado', lo que hace que el usuario
   bloqueado reciba 401 en lugar de 423.

10. Bitácora: registrar() escribe accion_sql, tabla_afectada, id_registro,
    detalle, ip_address, user_agent y fecha_hora. No usa new_data con
    { resultado: 'Exitoso' }.

11. No hay validación de correo con expresión regular, ni toast, ni botón
    Reintentar, ni timeout de 10 segundos.

================================================================
LIMITACIÓN DE ENTERPRISE ARCHITECT EN ESTA MÁQUINA
================================================================
La API de scripting de EA no crea atributos: se probaron 9 firmas de
AddAttribute y Attributes.AddNew y ninguna funciona, aunque crear elementos,
renombrarlos y cambiar estereotipos sí funciona. Por eso los 45 atributos y
las 27 operaciones se incorporan manualmente con los archivos tabulados
CU01_atributos.txt y CU01_operaciones.txt.
